# IAM-001 - Identity, session and RBAC foundation

## Scope

IAM-001 establishes deny-by-default API authentication, server-side role and
permission evaluation, revocable opaque sessions, account-status enforcement and
security audit events. It deliberately does not expose self-service role assignment
or Admin provisioning.

## Requirement traceability

| Requirement               | Implementation                                                                                  | Evidence                                              |
| ------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| AUTH-NFR-002              | Global authentication guard, active-account checks and protected `/auth/me`                     | Unit guard/session tests and unauthenticated E2E test |
| AUTH-011                  | Stable permission identifiers, role mappings and `@RequirePermissions` guard                    | Permission unit tests and Admin allow/deny E2E tests  |

| SYS-009                   | Deny-by-default global guards; only explicit public routes bypass authentication                | Public health tests and protected route tests         |

## API contracts

| Method | Route                 | Authorization                                    | Result                                          |
| ------ | --------------------- | ------------------------------------------------ | ----------------------------------------------- |
| `GET`  | `/api/v1/auth/me`     | Active bearer session                            | Resolved user, session, roles and permissions   |
| `POST` | `/api/v1/auth/logout` | Active bearer session                            | Revokes only the current session; returns `204` |
| `GET`  | `/api/v1/admin/me`    | Active bearer session plus `admin.portal.access` | Admin Portal authorization context              |
| `GET`  | `/api/docs`           | Public documentation                             | Interactive OpenAPI reference                   |

## Database evidence

Migration `20260923160000_iam_foundation` adds account type/status, roles,
permissions, user-role mappings, role-permission mappings and revocable sessions.
It seeds stable system role and permission identifiers but intentionally creates no
Admin user.

## Deferred at IAM-001 completion

Privileged Admin provisioning and MFA in the list below are now delivered by
`IAM-002`; the remaining items are still deferred.

The following remain incomplete and must not be represented as delivered:

- AUTH-001, AUTH-002 and AUTH-012: customer OTP request/verification and profile completion.
- AUTH-003 through AUTH-008: seller/business verification and approval lifecycles.
- AUTH-009 and remaining AUTH-NFR-005 behavior: privileged Admin login, provisioning and the MFA challenge/enrollment flow. Delivered by `docs/traceability/IAM-002.md`.
- AUTH-010 / AUTH-NFR-009: resource ownership and cross-account isolation in each future domain service.
- Password/recovery and device/session-management user interfaces.

Those flows will issue sessions through the IAM-001 session service after their own
security, rate-limit, audit and end-to-end acceptance work is implemented.
